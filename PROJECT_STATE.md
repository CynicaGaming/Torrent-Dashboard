## Recent work

### v0.5.166 — Movable and resizable torrent columns

Torrent-list columns can be rearranged by dragging their headers and resized by dragging their right edge, while the table always fits the torrent viewport without a horizontal scrollbar.

- Drag a column header to move it; an accent bar shows where it will land. A plain click still sorts.
- Drag the divider on a header's right edge to resize. Only that boundary moves: widening takes space from the columns to the right, nearest first, and narrowing gives it to the right-hand neighbour.
- Right-click the header to reset column widths, order, or both; double-click a divider to reset widths.
- Layouts are saved per browser and survive live refreshes and reloads.

### v0.5.165 — Restore Jellyfin 12 connections

Jellyfin 12 disabled the legacy X-Emby-Token authentication header by default, so the Jellyfin integration received HTTP 401. Torrent Dashboard now authenticates with the standard Authorization header, which Jellyfin has accepted since 10.8.

- Jellyfin status, scheduled tasks, and library refresh work again with Jellyfin 12.x servers.
- Existing Jellyfin API keys keep working; no settings changes are required.

### v0.5.164 — Harden live status, HTTPS, and history writes

Fixes reliability, performance, and information-disclosure issues found in a code review: a stalled HTTPS client can no longer freeze the dashboard, the status collector can no longer die permanently, and history writes and qBittorrent polling load are greatly reduced.

- One stalled HTTPS connection no longer blocks every other browser; the TLS handshake now runs on the per-connection thread and TLS 1.2 is the minimum.
- Per-torrent history rows are written once per sample interval instead of every second, and retention cleanup runs every 10 minutes instead of every second.
- Completion notifications are delivered from a background queue so slow webhooks no longer stall live status.
- The dashboard no longer overlaps status polls, discards stale responses after switching servers, and polls every 5 seconds while the tab is hidden.

### v0.5.163 — Confirm sign-up passwords and complete Pending users

Restores password confirmation during sign-up and gives administrators the full editable user form for Pending registrations before approval.

- Adds Confirm password back to the public Sign up form and rejects mismatched passwords in both the browser and registration endpoint.
- Gives Pending users the same Username, User group, First name, Last name, Email, Password, and Confirm password fields as active users.
- Saves administrator edits automatically before approving a Pending user, while keeping approval and rejection explicit.

### v0.5.162 — Unify Pending users and distinguish Sign up

Makes account creation visibly distinct from sign-in and manages Pending registrations in the normal Users list instead of a separate queue.

- Shows Sign up in the access tab while the Create account pane is active, then restores Sign in when returning to login or Recovery.
- Removes the separate Pending registrations settings card and shows Pending accounts directly in the normal Users accordion list.
- Marks unapproved accounts with a Pending badge and keeps Approve and Reject actions inside that user entry.

## Known issues

- Columns cannot be hidden; at narrow desktop widths some compact headers are truncated until widened.
- Backup encryption remains opt-in; unencrypted portable backups can contain saved client and integration credentials and should be stored securely.
- Windows executables are not code-signed yet.
